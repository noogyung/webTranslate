## 🚀 Git 자동 동기화 & 버전 관리 워크플로우 규칙

사용자의 단일 요청(턴)에 대한 코드 및 문서 수정 작업이 완료되면, 반드시 아래 5단계 프로세스를 순차적으로 수행하여 Git 커밋 및 원격 푸시를 완료해야 한다. (단, 단순 질문/조회 턴은 제외)

### 1. 버전 일관성 및 브랜치 라우팅
* `manifest.json`과 `package.json`의 `version` 필드는 항상 동일하게 동기화되어야 한다.
* 작업 대상 버전에 따라 적절한 브랜치로 분기/전환한다:
  * `1.0.x` 작업: `main` 브랜치 유지
  * `2.0.x` 이상 메이저/마이너 작업: `v{Major}.{Minor}-dev` 브랜치 (예: `v2.0-dev`, 미존재 시 생성 후 전환)

### 2. 문서 실시간 동기화 (Doc Sync)
* **`README.md`**: 신규 기능, UI 변경, 지원 엔진, 단축키 변경이 발생하면 반드시 커밋 전 최신 사양으로 수정한다.
* **`CHANGELOG.md`**: 버전 번호가 변경되거나 주요 기능/버그 수정 시 변경 이력을 누적 기록한다.

### 3. 무결성 및 패키징 빌드 검증 (Safety Guard)
* 커밋 전 NextCloud 동기화 락(`.git/index.lock`) 존재 여부를 확인하고 대기/제거한다.
* `npm run package`를 실행하여 크롬 확장 프로그램 패키징 및 문법 오류가 없는지 검증한다. 실패 시 커밋을 중단하고 즉시 수정한다.
* `.gitignore`에 등록된 비밀 파일(`*.env*`, `*.local.*`)이 스테이징되지 않도록 보장한다.

### 4. 규격화된 커밋 메시지 작성 (Conventional Commits)
* 반드시 작업 영역과 내용을 명확히 드러내는 구조화된 메시지를 작성한다:
  * 형식: `type(scope): 상세 작업 설명`
  * 예시:
    * `feat(image): 이미지 호버 캔버스 오버레이 렌더러 추가`
    * `fix(api): Gemini API 호출 시 레이트 리밋 지수 백오프 적용`
    * `docs(readme): 후원 링크 및 사용 가이드 최신화`
    * `refactor(popup): 툴바 드롭다운 UI 컴포넌트 모듈화`

### 5. 즉시 원격 푸시 (Immediate Push)
* 커밋 완료 즉시 작업 브랜치로 원격 푸시를 실행한다 (`git push origin <branch>`).
* 인증 또는 네트워크 예외로 인해 백그라운드 푸시가 지연/실패할 경우, 무한 대기하지 않고 사용자에게 터미널 실행 명령어를 안내한다.
